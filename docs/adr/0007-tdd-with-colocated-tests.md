# ADR-0007: TDD とコロケートしたユニットテストを開発規約にする

- ステータス: Accepted
- 日付: 2026-08-16
- 関連: [ADR-0003](0003-parameter-contract.md), [ADR-0012](0012-landmark-based-head-pose.md), [ADR-0014](0014-editor-features-on-demand.md)

## 背景

補間・変形・モデル検証は数値と境界値のロジックであり、画面の目視だけでは退行に気づけない。
一方でブラウザ・カメラ・GPU に依存する部分は自動テストの費用対効果が悪い。

## 決定

t-wada 氏の提唱する TDD サイクル(Red → Green → Refactor)に従う。テストは
`<module>.test.ts` として実装の隣に置き、Vitest の node 環境で実行する。

テスト可能性を保つため、ロジックはブラウザ API から切り離した純関数・純クラスとして書く。

- コア: モデル検証、グリッド生成、キーフレーム補間、パラメータストア、平滑化、Runtime
- デモ側でも、トラッキング値の正規化(`calibrateJawOpen` 等)とエディタの選択計算
  (`softSelectionWeights` 等)は純関数に切り出してテストする

ブラウザ実挙動(描画・カメラ)は手動確認とヘッドレスブラウザによるスモークで担保する。

## 影響

- アダプタを「MediaPipe を import しない純関数」として設計する動機が生まれ、結果として
  [ADR-0003](0003-parameter-contract.md) の境界が自然に守られている
- 変形の中間値・クランプ・不正モデルなど、目視では見落とす条件がテストで固定されている
- テストが書けない形になったら、それは設計が境界を跨いでいるサインとして扱う

## 却下した代替案

- **目視確認のみ**: 数値ロジックの退行を検知できない
- **E2E テスト中心**: カメラと GPU に依存するため不安定で、遅い
