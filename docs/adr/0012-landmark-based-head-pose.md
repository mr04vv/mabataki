# ADR-0012: 頭部姿勢はランドマーク幾何から推定し、全トラッキング値を較正して渡す

- ステータス: Accepted
- 日付: 2026-08-17
- 関連: [ADR-0003](0003-parameter-contract.md), [ADR-0007](0007-tdd-with-colocated-tests.md), [ADR-0010](0010-smoothing-outside-runtime.md)

## 背景

当初のカメラデモ計画では、MediaPipe の `facialTransformationMatrixes` から yaw / pitch / roll を
オイラー角分解する想定だった。実装時に次の問題が出た。

- 行列の軸規約と符号が不確かで、実機確認なしには正しさを保証できない
- 必要なのは角度そのものではなく、`-1..+1` に正規化された扱いやすい値である
- blendshape の生値をそのまま使うと、静止時に震え、かつ個人差のある可動域を使い切れない

## 決定

頭部姿勢はランドマークの幾何関係から推定し、全パラメータに較正を適用してから Runtime に渡す。

- **yaw**: 鼻(landmark 1)と左右輪郭(234 / 454)の相対位置から算出
- **roll**: 234 → 454 の傾き(`atan2`)から算出
- **共通の正規化**: デッドゾーンを引いてフルスケールで割る。`jawOpen` にはさらにガンマ 0.75 を
  掛け、話すときの実用域を広げる
- **ミラー規約**: カメラプレビューは鏡像表示のため、yaw / roll の符号を反転し、
  tracker-left を avatar-right に入れ替える(ユーザーが画面で見た向きにアバターが動く)
- デッドゾーン / フルスケール / ガンマは実測で調整する前提の較正ノブとして、名前付き定数にする

## 影響

- 静止時のノイズが消え、個人差のある可動域を使い切れる
- 行列の軸規約に依存しないため、MediaPipe 側の出力仕様変更に強い
- 純関数(`estimateHeadYaw` / `calibrateJawOpen` / `calibrateEyeOpen` など)として切り出しており、
  ユニットテストできる([ADR-0007](0007-tdd-with-colocated-tests.md))
- 較正はトラッカー固有の処理であり、コアには入らない([ADR-0003](0003-parameter-contract.md))

## 却下した代替案

- **変換行列からのオイラー角分解**: 軸規約と符号の不確かさに対して、得られる精度が見合わない
- **blendshape の生値をそのまま使う**: 震えと可動域不足で、実用的な追従にならない
